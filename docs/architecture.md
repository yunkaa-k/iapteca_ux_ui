# Архитектура iApteca

Актуализация: 20.11.2026. Основа — практические работы №1–3 и актуальные продуктовые экраны Figma **Screens**; **UI-Kit** задаёт компоненты и оформление.

## Приложение

Единое приложение Next.js 16 / React 19 / TypeScript. `src/app` содержит App Router и серверные API Routes; отдельные микросервисы и API Gateway не используются. Интерфейс построен на CSS Modules, Tailwind CSS и существующих UI-компонентах Radix. Типографика — Manrope.

- Главная, каталог, карточка товара, избранное и корзина используют существующие компоненты `src/components`.
- Клиентское состояние находится в `src/lib/store` (Zustand).
- Авторизация по email использует серверную cookie и коллекцию сессий; телефонного входа нет.
- Административные страницы управления препаратами, категориями, заказами и пользователями сохранены как полезный инструмент ведения собственных данных.
- `src/lib/logger.ts` сохраняет сообщения об ошибках и маскирование персональных данных. Отдельный Prometheus endpoint и реестр метрик удалены.

## Данные и локальная инфраструктура

`src/lib/db.ts` использует явно заданный `MONGODB_URI` и переиспользует подключение Mongoose при hot reload. Модели находятся в `src/lib/models.ts`, типы — в `src/lib/types.ts`.

Используются коллекции `users`, `usersessions`, `categories`, `medications`, `orders`. Промокоды не входят в лабораторные сценарии: их UI, API, модель, вычисление скидок и коллекция удалены. Старые документы заказов не мигрируются и не удаляются.

Next.js работает в Windows. `compose.yml` запускает только MongoDB 7 с аутентификацией, Replica Set `rs0` и постоянным named volume `iapteca_ux_ui_mongo_data`. Старый volume `iapteca_mongo_data` не используется. `.env.local` и `.local/mongo-keyfile` остаются только локально. Инструкция: [local-development.md](local-development.md).

`node_modules`, `.next`, `next-env.d.ts`, `pnpm-workspace.yaml`, конфигурации Next.js, TypeScript, Tailwind/PostCSS, ESLint, Vitest и `components.json` нужны приложению или инструментам разработки. Удалять их как старую инфраструктуру нельзя. Кэш TypeScript перенесён из корня в `.next/cache`.

## Дальнейшая работа

Аналоги, готовые аптечки, получение/оплата и результаты заказов необходимо продолжить по Figma. Для рецептов добавлены информационная страница `/prescription` и демонстрационный шаг `/cart/prescription` с отдельными файлами/статусами и блокировкой checkout до подтверждения; границы и сценарии описаны в [prescriptions.md](prescriptions.md). Список и детали демонстрационных заявок добавлены в личный кабинет через отдельный sessionStorage store с привязкой к аккаунту. Реальные заказы продолжают поступать из MongoDB. Серверный wrapper checkout передаёт ID локальной заявки в переиспользуемый CheckoutContent; новые модели базы для имитации не создаются. Bundle реализован отдельной коллекцией: фиксированный готовый товар, доступность по остаткам компонентов, списание в транзакции и возврат по снимку состава заказа. Подробности: [bundles.md](bundles.md). Рецепты и карта — демонстрационные сценарии. Мобильная версия и production на этом этапе не настраиваются.

Проверки: Vitest, `pnpm exec tsc --noEmit`, `pnpm lint`. Удаление старой инфраструктуры не заменяет будущую проверку соответствия дизайну, a11y и UX-валидацию перед защитой.

## Оформление и подтверждение — 20.11.2026

`CheckoutContent.tsx` теперь реализует контакты, получение, демонстрационную карту и способ оплаты. `lib/checkout.ts` объединяет клиентскую/серверную валидацию; доставка курьером — 59 грн, самовывоз — бесплатно. Внешняя карта, оплата, SMS и email не подключены: тексты уведомлений воспроизводят макет, фактическая отправка отсутствует.

`POST /api/orders` сохраняет необязательный блок checkout (контакты, получение и оплата) и subtotal; старые заказы без этих полей остаются совместимыми. Обычный заказ допускается гостем, рецептурный требует входа и демонстрационного сценария проверки. Цены берутся из Medication, списание остатков и создание заказа выполняются в одной транзакции, включая заказ из одного товара. Администратор видит гостевые заказы и контактные данные; публичного поиска заказа по ID нет.

`checkoutStore.ts` хранит черновики и снимки подтверждения в sessionStorage. Снимок записывается до очистки купленных строк корзины. `/order/result?order=...` показывает снимок текущей сессии, а не загружает произвольный заказ по ID. Для заказа аккаунта дополнительно проверяется владелец. Закрытие вкладки удаляет локальный снимок, сам заказ остаётся в MongoDB. Повторная отправка при сетевой неопределённости пока не защищена серверным ключом идемпотентности; кнопка блокирует одновременное повторное нажатие.
