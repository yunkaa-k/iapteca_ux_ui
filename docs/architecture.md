# Архитектура iApteca

Актуализация: 23.11.2026. Основа — практические работы №1–3. Продуктовые экраны берутся из **Screens**, компоненты и оформление — из **UI-Kit**. Язык интерфейса — украинский.

## Приложение

Единое приложение Next.js 16 / React 19 / TypeScript. `src/app` содержит App Router и серверные API Routes; отдельные микросервисы и API Gateway не используются. Интерфейс построен на CSS Modules, Tailwind CSS и существующих UI-компонентах Radix. Типографика — Manrope.

- Главная, каталог, карточка товара, избранное и корзина используют существующие компоненты `src/components`.
- Zustand хранит корзину, избранное и историю поиска в `localStorage`. Черновики checkout, снимки результата заказа и демонстрационные заявки на проверку рецепта хранятся в `sessionStorage` текущей вкладки.
- Авторизация по email использует серверную cookie и коллекцию сессий; телефонного входа нет.
- Административные страницы управления препаратами, категориями, заказами и пользователями сохранены как полезный инструмент ведения собственных данных.
- `src/lib/logger.ts` сохраняет сообщения об ошибках и маскирование персональных данных. Отдельный Prometheus endpoint и реестр метрик удалены.

## Данные и локальная инфраструктура

`src/lib/db.ts` использует явно заданный `MONGODB_URI` и переиспользует подключение Mongoose при hot reload. Модели находятся в `src/lib/models.ts`, типы — в `src/lib/types.ts`.

Используются коллекции `users`, `usersessions`, `categories`, `medications`, `bundles` и `orders`. Старые документы заказов читаются без миграции.

Next.js работает в Windows. `compose.yml` запускает только MongoDB 7 с аутентификацией, Replica Set `rs0` и постоянным named volume `iapteca_ux_ui_mongo_data`. Старый volume `iapteca_mongo_data` не используется. `.env.local` и `.local/mongo-keyfile` остаются только локально. Инструкция: [local-development.md](local-development.md).

`node_modules`, `.next`, `next-env.d.ts`, `pnpm-workspace.yaml`, конфигурации Next.js, TypeScript, Tailwind/PostCSS, ESLint, Vitest и `components.json` нужны приложению или инструментам разработки. Удалять их как старую инфраструктуру нельзя. Кэш TypeScript перенесён из корня в `.next/cache`.

## Продуктовые сценарии

- Сравнение аналогов открывается внутри карточки товара. Готовые аптечки имеют фиксированный состав, рассчитывают доступность по остаткам компонентов и восстанавливают их по снимку состава при отмене. [Аптечки](bundles.md)
- `/cart/prescription` имитирует отдельную проверку каждого рецептурного товара. Кабинет показывает заявки из `sessionStorage` с привязкой к аккаунту и заказы из MongoDB. Подтверждённая заявка открывает checkout со своим снимком товаров. [Рецепты](prescriptions.md)
- `/checkout` принимает контактные данные, способ получения и оплаты. `/order/result` показывает снимок результата в текущей вкладке. В кабинете доступны детали серверного заказа, отмена в допустимом статусе и повтор демонстрационной оплаты при отказе. [Оформление](checkout.md)

Проверки кода выполняются через Vitest, `pnpm exec tsc --noEmit` и `pnpm lint`. Предстоящая визуальная сверка, адаптация под мобильные экраны, проверки доступности и UX перечислены в [плане практической работы](../conductor/subagent-task-plan.md).

## Оформление и подтверждение

`CheckoutContent.tsx` реализует контакты, самовывоз по демонстрационной карте, курьерскую доставку и способ оплаты. `lib/checkout.ts` объединяет клиентскую и серверную валидацию. Доставка курьером стоит 59 грн, самовывоз бесплатный. При онлайн-оплате API получает исход демонстрации, а номер карты и CVV остаются в состоянии формы.

`POST /api/orders` сохраняет блок checkout и subtotal. Обычный заказ доступен гостю. Для рецептурного заказа сервер требует вход, а клиентский сценарий — демонстрационное подтверждение. Сервер берёт цены из Medication и Bundle, списывает остатки и создаёт заказ в одной транзакции. Гостевые заказы с контактными данными доступны администратору через защищённый API.

`checkoutStore.ts` записывает снимок результата перед очисткой купленных строк корзины. `/order/result?order=...` читает снимок текущей вкладки и проверяет владельца для заказа аккаунта. После закрытия вкладки заказ остаётся в MongoDB и доступен владельцу в истории.

Checkout отправляет `Idempotency-Key` при создании заказа. Повтор той же попытки с теми же данными может получить уже созданный заказ. Сервер сверяет владельца и параметры запроса до записи остатков. Интеграционная проверка потерянного ответа и параллельного повтора отслеживается в [плане практической работы](../conductor/subagent-task-plan.md).
