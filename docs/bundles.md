# Готовые аптечки

Актуализация: 20.11.2026. Маршруты: `/kits`, `/kits/[slug]`. Старые ссылки `?kit=travel` перенаправляются на карточку. Источник внешнего вида — актуальные Screens `1690:8226` и `1690:8542`; количество 2 воспроизводится контролом той же карточки. Старый кадр `1742:8648` через MCP не найден, поэтому его прежнее содержимое не считалось актуальным.

## Данные

`Bundle` — отдельная коллекция `bundles`: slug, название, описание, назначение, цена набора, изображение, фиксированные компоненты (Medication ID, количество, название), compositionConfirmed, isDeleted. Самостоятельного stock у аптечки нет. Доступность = минимум floor(остаток компонента / расход на один набор); повторяющиеся компоненты агрегируются. Неизвестный/удалённый/некорректный компонент, пустой или неподтверждённый состав блокирует покупку. Состав покупатель не меняет.

Склад материалов использует существующую Medication. `inventoryOnly=true` исключает материалы из покупательского каталога, его фасетов и поиска, но позволяет администратору видеть и редактировать их остатки через защищённый параметр inventory=true. Нулевая цена у служебной записи — не цена продажи: материал отдельно не продаётся, попытка обычного заказа такого ID блокируется. Клиент не может изменять состав через API: у `/api/bundles` доступны только GET.

## Корзина, заказ и отмена

Bundle адаптируется к существующему товарному контракту через BundleProduct (`kind=bundle`, ID, slug и рассчитанный stock). Переиспользованы cartStore, favoritesStore и ProductFeedback. Cart/Favorites ведут на `/kits/[slug]`, bulk-add избранного проверяет `/api/bundles/[id]`. Цены и доступность в API заказа повторно проверяются по серверным моделям.

Старые OrderItem без kind по-прежнему означают Medication. Новая строка kind=bundle сохраняет ID набора в существующем поле medication, цену, название, описание, изображение, slug и состав на момент заказа. В checkout передаётся kind, но клиентские цена и состав не используются для складской операции. Комплектация не разворачивается в отдельные оплачиваемые строки, аптечка остаётся одним товаром.

Списание компонентов, обычных лекарств и создание смешанного заказа выполняются в одной MongoDB-транзакции. Условие stock >= необходимое количество защищает от отрицательных остатков; при дефиците откатывается весь заказ. При конфликте записи покупка повторяется ограниченное число раз.

Владелец может отменить заказ в допустимом статусе из его деталей в кабинете. Административная и пользовательская отмена используют `PATCH /api/orders/[id]`. Сервер меняет статус и восстанавливает компоненты по сохранённому составу заказа в одной транзакции. Повторный запрос для уже отменённого заказа возвращает его текущее состояние. Оплаченный демонстрационный заказ при отмене получает статус возврата `pending`. [Оформление и статусы](checkout.md)

## Заполнение и проверка

- `node scripts/seed-local-bundles.mjs`: только localhost/127.0.0.1, база iapteca, rs0 PRIMARY. Добавляет 5 наборов и 11 служебных материалов с демонстрационным остатком 30. Устойчивые ID; повторный запуск ничего не дублирует и не изменяет существующие остатки. Новые реальные данные или экспертные составы потребуют отдельного явного обновления, seed их не перезаписывает.
- `node scripts/test-local-bundle-orders.mjs`: приложение должно работать на localhost:3000; локальная MongoDB rs0. Проверены обычный товар, 2 набора, смешанный заказ, нехватка компонента с rollback, повторная отмена, возврат по старому составу, три параллельные покупки при наличии двух наборов, доступ администратора к гостевым заказам и отсутствие публичного списка. Временная тестовая административная сессия и все записи со случайной меткой удаляются в finally; реальные документы и остатки не затрагиваются. Секреты не выводятся.
- `src/test/bundles.test.ts`, `src/test/bundle-orders.test.ts`: модульные проверки расчёта и совместимости.
- В браузере сверены каталог и travel с Figma, выбор 2 наборов, сумма 498 грн, избранное и переходы из него/корзины. Изображения локальные, общие Header/Footer не переписаны.

## Ограничения

Цена и остаток в локальных снимках корзины и избранного могут устареть. Сервер повторно проверяет их при покупке. Компоненты редактируются как товарные записи через административный API, а способы управления составом Bundle и экспертное утверждение наборов остаются отдельными продуктовыми задачами.
