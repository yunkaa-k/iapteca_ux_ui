# Вход и регистрация iApteca

Обновлено 23 ноября 2026 года. Маршруты аккаунта: `/login`, `/register`, `/reset-password` и `/profile`.

## Аккаунты

- Новая регистрация использует email, пароль и согласие с политикой. Email приводится к нижнему регистру и очищается от крайних пробелов. Пароль — минимум 8 символов и максимум 72 UTF-8 байта, чтобы bcrypt не обрезал его незаметно.
- Вход и регистрация работают только по email. Телефонный переключатель удалён; запросы только с телефоном отклоняются API. Существующие документы с телефоном не удаляются, но вход по телефону не поддерживается. Перенос старого аккаунта на email требует отдельного подтверждённого сопоставления владельца: автоматически придумывать адреса нельзя.
- Пароли хешируются bcrypt. Роль клиента не принимается из запроса: новые пользователи получают CUSTOMER.
- Согласие email-пользователя записывается в `privacyAcceptedAt`.
- Регистрация сразу создаёт сессию. После входа приложение открывает главную или возвращает к сохранённому шагу проверки рецепта. Отправка писем и подтверждение адреса выходят за границы учебного сценария.

## Индексы существующей локальной БД

Перед первым созданием email-аккаунтов выполнить:

```powershell
node scripts/prepare-email-auth.mjs
```

Скрипт допускает только локальную MongoDB и базу `iapteca`. Сначала создаёт уникальные частичные индексы `phone_unique_present` и `email_unique_present`, затем убирает прежний полный уникальный индекс телефона. Это позволяет хранить несколько пользователей без телефона, сохраняя уникальность заданных телефонов. Документы пользователей не изменяются. При конфликте новых индексов скрипт останавливается до удаления старого. Повторный запуск допустим.

## Сессии

Cookie `auth_id` содержит случайный 256-битный токен, а не ID пользователя. В коллекции `usersessions` хранятся SHA-256 хеш токена, пользователь и срок действия (24 часа). Cookie имеет HttpOnly, SameSite=Lax и Secure в production. Время истечения проверяется при каждом запросе; TTL-индекс очищает старые записи. Выход удаляет сессию в MongoDB, поэтому повторное использование токена не авторизует пользователя. После обновления старые cookie с ID недействительны: нужно войти заново.

Профиль и административная таблица отображают email либо старый телефон. API не возвращает пароль и хеш сессии.

## Изменение и демонстрационное восстановление пароля

В профиле пользователь может изменить пароль. `POST /api/profile/password` проверяет сессию и текущий пароль, валидирует новый и сохраняет его bcrypt-хеш.

`/reset-password` демонстрирует ввод email, кода `482913` и нового пароля с подтверждением. Результат на экране поясняет, что пароль аккаунта сохранён прежним. Все шаги формы выполняются локально. Прежний серверный маршрут `/api/auth/reset-password` отвечает 503.

## Проверка

```powershell
pnpm test:run
pnpm exec tsc --noEmit
pnpm lint
node scripts/test-local-auth.mjs
```

Последняя команда требует работающие Next.js на `localhost:3000` и локальную MongoDB. Создаёт одноразовые аккаунты на домене `example.test`, проверяет сценарии и отказ телефонных запросов, затем удаляет только свои аккаунты и сессии. Пароли, URI и cookie не выводятся. Существующие пользователи не затрагиваются.

Публикация учебного демо выполняется по отдельной команде владельца проекта. Подключение почтового восстановления относится к отдельному продуктовому сценарию.
